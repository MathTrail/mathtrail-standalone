## Что делать

### 1. `internal/infra/seal`

**Назначения — закрытый список с однобуквенными метками**, как в таблице `02-auth` и в `04-profile`:

| Назначение | Метка | Кто им пользуется |
|---|---|---|
| `code` | `c` | T48 |
| `access` | `a` | T49 |
| `refresh` | `r` | T49 |
| `client` | `d` | T47 |
| `state` | `s` | T48 |
| `consent` | `k` | T48 |
| `task-answer` | `t` | T44, T45 |

**Ключ и его идентификатор.** Ключ — 32 случайных байта; key id — первые шесть base64url от SHA-256 самого ключа, так что ключ и его id нельзя сконфигурировать порознь. Идентификатор считается один раз при разборе ключа.

**Связка.** Текущий ключ запечатывает и распечатывает, предыдущий — только распечатывает. Предыдущего может не быть. Неизвестный key id — отказ, неотличимый для вызывающего от неверного шифротекста.

**Запечатывание.** Подключ на назначение — HKDF-SHA256 с info `mathtrail/v1/<purpose>`; XChaCha20-Poly1305 (`golang.org/x/crypto/chacha20poly1305`, `NewX`) со случайным 192-битным nonce; additional data — назначение, key id и то, к чему вызывающий привязывает шифротекст (пользователь и задача в терминах T24). Наружу — `mt1.<метка>.<kid>.<base64url(nonce‖ciphertext)>`.

Привязка обязана совпасть при открытии: без неё запечатанный ответ одного ребёнка не отличается от ответа другого ничем, кроме содержимого.

**Ошибки** — предсказуемый набор для `errors.Is`: неразбираемая форма, чужое назначение, неизвестный ключ, не прошедшая проверку целостность. Наружу пользователю ни одна не пересказывается (T47–T49 отвечают своими формулировками), в лог — одна строка без шифротекста.

### 2. Конфигурация

`MATHTRAIL_SEAL_KEY_CURRENT` (обязательная) и `MATHTRAIL_SEAL_KEY_PREVIOUS` (нет) — имена уже зафиксированы в SPEC 11 и в `infra/terraform/service.tf`, менять нечего. Объявляются в `internal/config` одной декларацией каждая, как требует R18; `Validate()` отказывает с именем переменной, если ключ не разбирается из base64 или в нём не 32 байта.

Ключ не попадает ни в лог, ни в сообщение об ошибке — только его id.

### 3. Сборка при старте

Связка строится в `app.NewContainer` рядом с контентом и по тем же правилам: не собралась — процесс не стартует. В строке лога `content loaded` появляется соседка: key id текущего ключа и есть ли предыдущий. Ключей в ней нет.

### 4. Тесты

- Табличные на каждый отказ из T24: round trip; подменённый байт; чужая привязка; чужое назначение; неизвестный key id; ротация (старое читается предыдущим, новое пишется текущим); неверная длина ключа при старте.
- Property-тест (R39): для любого содержимого, назначения и привязки — открытое равно запечатанному; шифротекст с изменённым байтом не открывается никогда; шифротекст одного назначения не открывается другим.
- Fuzz на разбор токена: это единственный вход, который приходит снаружи и целиком под контролем того, кто его прислал.
- Каждая проверка доказывается падающим тестом при её отключении (CLAUDE.md, «Tests»).
