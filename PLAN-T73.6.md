# T73.6 — архив статьи A на Zenodo (план)

## Контекст

T73.5 (R254) подготовила для Zenodo всё, кроме самой записи. Процесс `zenodo.yml` запускается только руками и только с `main`. Инструмент `research/tools/zenodo` кладёт пакет последнего выпуска `paper-a/…` в черновик (шаг draft) и публикует этот черновик (шаг publish). Описание записи лежит в `research/release/zenodo.json`. Записи пока нет, поэтому именная статья печатает `\TBD{K11: the artifact's DOI}` (`research/paper-a/sections/discussion.tex:8`), а «Code and data» на странице «Исследование» ведёт на репозиторий.

Состояние на 2026-10-18. Выпусков статьи два, последний `paper-a/6123b8a56368` от 2026-10-08. `paper.yml` зелёный на каждом мерже, но выпусков больше не делал: пакет и текст с тех пор не менялись.

**Где исполнять.** Эта сессия не в devcontainer: `MATHTRAIL_DEVCONTAINER` пуст, `just` нет, developers.zenodo.org из её сети не открывается. Оба захода исполняются в devcontainer (жёсткое правило CLAUDE.md).

## Решения автора (2026-10-18)

1. **Новая версия на Zenodo выходит только с новым пакетом.** Если изменились только текст статьи, анонимный пакет или PDF, шаг draft ничего не создаёт. Сам пакет текста статьи не содержит (`release/assemble.sh` кладёт только `generated/numbers.tex` и `live.txt`), поэтому DOI, вписанный в статью, даст новый тег `paper-a/…` с тем же пакетом.
2. **Песочницы sandbox.zenodo.org нет.** Репетицией служит черновик на zenodo.org: он виден только владельцу и удаляется. Навсегда остаются только файлы опубликованной версии, а описание записи правится и после публикации.
3. **DOI вписывается после publish.** Общий DOI записи берётся из ответа Zenodo (`conceptdoi`) и не вычисляется из черновика.
4. **Одна задача в два захода.** `[x]` ставится после второго захода, первый сдаётся как промежуточный.

Номер решения — следующий свободный на момент записи, сейчас R309.

## Заход 1: правило версий (до шагов автора на Zenodo)

**Инструмент `research/tools/zenodo`:**
- `api.go`: у `File` появляется `Checksum string \`json:"checksum"\``. Формат суммы в списке файлов депозита сверить с developers.zenodo.org до кода, по правилу 6. Бакет отвечает `md5:<hex>`, а список файлов, по памяти, отдаёт голый hex, поэтому сравнение снимает приставку `md5:`.
- `steps.go`, `draftFor`, ветка с `record`. Сейчас после `latestPublished` проверяется только совпадение имени версии. Добавляется проверка «последняя опубликованная версия уже держит этот пакет»: её единственный файл называется так же, как архив, и его MD5 совпадает с MD5 архива. Тогда ответ тот же, что для уже опубликованной версии (`latest, true`): ни `newversion`, ни черновика. Файл без суммы — отказ с понятной ошибкой, а не «пакет новый»: лишняя версия на Zenodo вечна.
- MD5 архива считает один небольшой помощник (`md5Of(path)`). Проверка сохранённого в `replaceFiles` остаётся как есть.
- `Draft`: сообщение о том, что делать нечего, называет версию, которая уже держит пакет (`d.Metadata.Version`). Например: «Version paper-a/aaa of record 1001 holds this archive already, so there is nothing to draft.» Так оно верно в обоих случаях: и при том же теге, и при новом теге с тем же пакетом. Ошибка `nothingToPublish` добавляет, что шаг draft скажет, если пакет уже в записи.
- Первая запись (`record == ""`) не меняется.

**Тесты (`zenodo_test.go`, `fake_test.go`):**
- подставной Zenodo отдаёт в списке файлов `checksum` в том виде, который даёт документация;
- новый тест: draft `aaa` «first» → publish → draft `bbb` в записи 1001 с тем же «first» говорит, что делать нечего, и называет `paper-a/aaa`; число депозиций прежнее, запроса `newversion` в `f.requests` нет. С выключенной проверкой тест красный: проверить, сломав её;
- уже есть `TestTheNextVersionHoldsItsOwnArchiveAlone`: другие байты дают новую версию, так что проверка не слишком широка;
- тест на отказ: файл последней версии пришёл без суммы, значит ошибка, и черновика нет.

**`zenodo.yml`:** только комментарий в шапке. Шаг draft либо кладёт пакет в черновик, либо говорит, что запись его уже держит.

**Документы:**
- новое решение R309 в `docs/decisions.md`. Версия на Zenodo выходит только с новым именным пакетом, а шаг draft сравнивает MD5 с последней версией записи. Пробного прогона в песочнице нет. DOI вписывается после publish, из ответа Zenodo. *Why:* пакет текста не содержит; версия на Zenodo навсегда; прежний Zenodo отказывал версии с теми же файлами; черновик на zenodo.org удаляется. *Rejected:* версия на каждый запуск; PDF в записи, что меняет R254 и делает запись препринтом; песочница; DOI, вычисленный из черновика. В R254 — пометка-ссылка на R309;
- RUN.md, тело T73.6: «Решено (2026-10-18, R309)» вместо «Решить в начале» и порядок шагов автора, как ниже.

**Проверки:** `just research ci-lint`, `just research ci-test`, `just ci-lint`, `just ci-test`, затем `/code-review high` по правилам CLAUDE.md (новые файлы — через `git add -N`). Отчёт; коммит и мерж делает автор.

## Шаги автора между заходами

1. Аккаунт на zenodo.org и токен с правами `deposit:write` и `deposit:actions`.
2. На GitHub — окружение `zenodo`, куда пускают только ветку `main`, и в нём секрет `ZENODO_TOKEN`.
3. После мержа захода 1 запустить `zenodo.yml` шагом draft, пока `ZENODO_RECORD` пуст. В черновике проверить: название, описание, автор «Riazanov, Aleksandr», лицензия MIT, один файл `paper-a-artifact.tar.gz`, версия `paper-a/6123b8a56368`.
4. Запустить шаг publish. Из итога прогона взять DOI версии, номер записи (concept id) и общий DOI.
5. Номер записи положить в переменную `ZENODO_RECORD` окружения `zenodo`.
6. Снова запустить draft на тот же выпуск. Ожидается «… holds this archive already»: второй записи и второй версии нет.

## Заход 2: DOI в статье и на сайте (после publish)

**Статья:**
- `research/paper-a/preamble.tex`: в именной ветке, рядом с `\ArtifactURL`, появляется `\newcommand{\ArtifactDOI}{\url{https://doi.org/10.5281/zenodo.<N>}}`. В анонимной ветке макроса нет. Поэтому `\ArtifactDOI`, случайно поставленный в общий текст, роняет анонимную сборку, а не выдаёт автора: запись Zenodo всегда называет авторов (K11);
- `sections/discussion.tex:8`: `\TBD{K11: the artifact's DOI}` → `\ArtifactDOI`, только в ветке `\else`;
- проверка чисел, набранных руками: `\url` в списке команд, чьи аргументы пропускаются (`research/tools/handtyped/handtyped.go:28-34`), а преамбулу проверка не читает. Регистрировать в `names-with-digits.txt` нечего, это подтверждается прогоном `just research paper-a`. Там же видно, что строка не вылезает за поле: ошибка `Overfull \hbox`;
- `paper-a/draft.md:190` и `draft.ru.md:192`: `[TBD: K11]` → адрес DOI, обе копии в одной правке (CLAUDE.md);
- `paper-a/submission.md:23`: именная версия печатает DOI.

**Сайт:**
- `web/src/site/brand.ts`: новая константа `artifactURL = "https://doi.org/10.5281/zenodo.<N>"` с комментарием. Это место, где архив хранится навсегда. `sourceURL` не трогаем: её берут подвал, «О нас», главная и ссылка на issues;
