# План приложения MathTrail для телефона и браузера

> Что строим, говорит спецификация [docs/mobile-app.md](docs/mobile-app.md), а этот файл задаёт порядок работы над самим приложением: маленькие задачи, которые запускаются по одной. Спецификацию написала фаза 19 плана MathTrail, она лежит в [архиве](docs/plan/phase-19.md). Правки самого MathTrail, которые нужны приложению, сюда не входят. Они перечислены в §12 спецификации, и задачи на них ставит RUN.md MathTrail отдельным моим решением. Пока нового репозитория нет, этот файл лежит здесь, рядом с RUN.md MathTrail. Новый репозиторий начинается с копий обоих файлов, и там этот файл становится его RUN.md.

## Как пользоваться

Задача запускается одной фразой в новой сессии Claude Code: «Выполни задачу П04 из RUN.APP.md». В новом репозитории файл называется RUN.md, и фраза меняется так же.

**Правила для исполнителя (Claude):**

1. Делать только указанную задачу. Файлы других задач не трогать, кроме того, что задача прямо требует.
2. Сначала прочитать CLAUDE.md, саму задачу и разделы спецификации, на которые она ссылается. Если задача противоречит спецификации или чего-то не хватает, остановиться и спросить. Дыра записывается строкой в таблицу 3 этого файла или в §14 спецификации.
3. Задачи до П03 кода не пишут и идут в этом репозитории: они меняют только этот файл и спецификацию `docs/mobile-app.md`. С П03 работа идёт в новом репозитории, внутри его devcontainer. Исключения те, что назвала спецификация (§13.9): сборка под iOS идёт на macOS-раннере в CI, а проверки идут на моих устройствах.
4. Живой прогон, вызов API Anthropic на моём ключе, действие в Google Cloud, в магазинах и у платёжных сервисов начинать только после предупреждения, которое называет ожидаемую стоимость.
5. Код SDK, протоколов и API писать по документации закреплённой версии, а не по памяти. Это касается MCP TypeScript SDK и Go SDK, `anthropic-sdk-go`, Capacitor, RevenueCat, Paddle, StoreKit и Play Billing.
6. Задача с кодом заканчивается зелёными проверками нового репозитория (`just ci-lint`, `just ci-test`, а для веб-слоя ещё `just ci-web`) и `/code-review high`, как велит его CLAUDE.md.
7. Не коммитить: коммит делаю я после проверки.
8. В конце короткий отчёт по-русски: что сделано, какие файлы, как проверить, что нашло ревью, что осталось открытым.
9. После выполнения отметить задачу в таблице 1: `[ ]` → `[x]`. Вопрос ко мне, который остался без ответа, встаёт строкой в таблицу 3, а то, что отложено сознательно, строкой в таблицу 4.
10. Правки MathTrail отсюда не делаются. Если задаче нужна правка MathTrail, которой ещё нет, задача берёт временную замену из таблицы 2, а саму правку я ставлю в план MathTrail.
11. Если задача оказалась больше одной проверки, а это примерно 30–60 минут чтения, до начала предложить, как её разбить.

**Статусы:** `[ ]` — не начата, `[x]` — выполнена (отмечает исполнитель), `[-]` — не делаем по моему решению, `[?]` — отложена по моему решению. Причина и срок возврата пишутся в начале тела задачи.

**Кто:** «Claude» — делает исполнитель, я проверяю; «Claude, проверяю я» — тексты, которые я вычитываю построчно; «я + Claude» — часть шагов делаю я: решения, аккаунты, консоли, устройства.

**План:** «да» — задачу сначала прогнать в режиме планирования, потому что до кода в ней нужно принять решения, которых нет в спецификации. «—» — запускать сразу.
