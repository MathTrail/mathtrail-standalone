# Калибровка текстовых рисунков (T58)

**Статус: откалибровано без устройств, подтверждается в T62 и T63.** 2026-09-30. Пределы рисунка подобраны замером настоящего виджета в Chromium и прогоном модели в `just play`, как решил автор: на телефонах и в ChatGPT их подтверждают приёмки. Итог (R138): ширина 30 ячеек и высота 12 строк остаются, теперь как измеренные; набор символов сужен с четырёх целых блоков Unicode (368 символов) до 65; добавлена мягкая обратная проверка меток — каждую метку рисунка вопрос должен назвать.

## Что это

О-11а требует найти допустимый размер рисунка проверкой на реальных мобильных и веб-виджетах. До T58 пределы были консервативными: 30 ячеек — сколько спайк T03 показал на карточке телефона шириной 353 px, 12 строк — на глаз, символы — целые блоки стрелок, псевдографики, блоков и фигур. Задача ещё просила по живым рисункам моделей решить, нужна ли обратная проверка меток.

## Метод

- **Набор рисунков** — сервер калибровки `cmd/drawings`, рецепт `just drawings`: 18 рисунков на настоящей карточке задачи — рамки шириной 24–44 ячейки с линейкой (1–8), высотой 12–20 строк (9–11), разрешённые классы символов против строки ASCII-цифр (12–15), исключённые символы для сравнения (16), два каркаса (17–18). Автор посмотрел в Claude на телефоне прежнюю версию из 17 рисунков, до сужения набора: «всё нормально»; кнопки оценок не нажимал.
- **Замер** — витрина виджета (`just web-preview`), кадр задачи, рисунок подменён в настоящей карточке, ширина кадра — ширина карточки хоста. Браузер — Chromium из образа Playwright 1.63, движок Android WebView и Chrome. Шрифты — заместители платформ:
  - Liberation Mono (`fonts-liberation` 2.1.5-3): набор символов WGL4, как у Droid Sans Mono на Android и Consolas на Windows;
  - DejaVu Sans Mono (`fonts-dejavu-core` 2.37-8): на нём построен Menlo, метрики те же, что у SF Mono на iOS и macOS;
  - Noto Sans Mono (`fonts-noto-mono` 20201225-2).
- **Живые рисунки модели** — `just play`: Claude Code 2.1.280, модель `claude-sonnet-5`, локальный сервер, профиль «Тест», 4 класс, 12 задач по десяти темам, у которых есть каркасы. Сервер собран до изменений T58, так что задачи проверялись по старым правилам.

Кегль рисунка 14 px, ячейка — 8,4 px во всех трёх шрифтах.

| 353 px | 293 px | 34 | Claude на iPhone (T03) |
| 360 px | 300 px | 35 | |
| 375 px | 315 px | 37 | |

Рамки 32 ячейки и шире на карточке 320 px прокручиваются вбок внутри своей рамки (так устроен виджет с T55), 36 и шире — уже на 353 px.

## Высота

Карточка 390 px, от верха вопроса до низа последнего варианта:

| Высота рисунка | Сам рисунок | Вопрос + рисунок + пять вариантов |
|---|---|---|
| 12 строк | 262 px | 664 px |
| 16 строк | 342 px | 744 px |
| 20 строк | 422 px | 824 px |

На телефоне 390×844 чату остаётся около 640 px за вычетом строки состояния, шапки и поля ввода: уже при 12 строках вопрос, рисунок и варианты занимают весь экран.

## Символы

Строки каждого класса против строки ASCII-цифр той же длины, 29 ячеек (243,6 px):

| Строка | Liberation Mono | DejaVu Sans Mono | Noto Sans Mono |
|---|---|---|---|
| Псевдографика `┌─┬┐ │ ├┼┤ └┴┘` | ровно | ровно | ровно |
| Блоки `█ ▓▒░ ▀▄ ▌▐` | ровно | ровно | ровно |
| `■□`, `●○` | ровно | ровно | ровно |
| `▲△` | 280 px (+36) | ровно | 361 px |
| `◆◇` | 319 px (+75) | ровно | 487 px |
| `←→`, `↑↓`, `↔↕` | ровно | ровно | ровно |
| `⇐⇒` | 348 px (+104) | ровно | 487 px |

В Liberation Mono съехавшие глифы Chromium берёт из пропорционального DejaVu Sans: в самом шрифте их нет. Noto Sans Mono рисует их своими, но вдвое шире.

Посимвольно, по всем 368 символам четырёх блоков — сколько рисуются ровно в одну ячейку во всех трёх шрифтах:

| Блок | Всего | Ровно везде | Выпадают в Liberation / DejaVu / Noto |
|---|---|---|---|
| Стрелки U+2190–21FF | 112 | 9 | 100 / 0 / 101 |
| Псевдографика U+2500–257F | 128 | 40 | 88 / 0 / 0 |
| Блоки U+2580–259F | 32 | 8 | 24 / 0 / 0 |
| Фигуры U+25A0–25FF | 96 | 24 | 72 / 0 / 40 |

Из 81 символа, ровного везде, 12 (`◌◐◑◒◓◔◕◖◗`, `↚↛↮`) есть в Liberation Mono, но не входят в WGL4, так что на Droid Sans Mono и Consolas их нет. Ещё четыре — `↔↕▪▫` — входят в WGL4 и во всех трёх шрифтах ровные, но это ещё и эмодзи: если в шрифте телефона такого символа нет, телефон может взять его из шрифта эмодзи и нарисовать цветной картинкой в две ячейки, а WebKit и настоящих шрифтов телефонов замер не видел (замечание 33 SPEC). Они тоже исключены. Разрешены 65 символов (`checks.DrawingCharacters`):

- псевдографика — одинарные и двойные линии: `─│┌┐└┘├┤┬┴┼═║╒╓╔╕╖╗╘╙╚╛╜╝╞╟╠╡╢╣╤╥╦╧╨╩╪╫╬`;
- блоки: `▀▄█▌▐░▒▓`;
- фигуры: `■□▬▲►▼◄◊○●◘◙◦`;
- стрелки: `←↑→↓`.

Каркасы и все 24 эталонных рисунка уже обходились этим набором. Вне его был только каркас часов: его `purpose` велел рисовать стрелки через `╱` и `╲`, теперь через `/` и `\`.

## Живые рисунки модели и обратная проверка меток

| Тема | Рисунок | Метки | Названы в вопросе |
|---|---|---|---|
| `geometry.grid` | да | A B 1 2 | да: «A1, A2 и B1», «строки A и B», «столбцы 1 и 2» |
| `logic.sets` | да | P M | да: «(P)», «(M)» |
| `counting.gaps` | нет | | |
| `logic.ordering` | нет | | |
| `time.clocks` | нет | | |
| `algorithms.weighing_pouring` | нет | | |
| `fractions.parts` | нет | | |
| `ratio.sharing` | да | A B | **нет**: вопрос говорит «Аней и Борей», но нигде не связывает их с A и B |
| `number.divisibility` | нет | | |
| `time.calendar` | нет | | |
| `geometry.grid` | нет | | |
| `logic.sets` | да | S B | да: «(S)», «(B)» |

Модель нарисовала 4 из 12, и каждый раз там, где рисовал бы ребёнок (R69): площадь сетки, распилка, часы и календарь остались словами. Один рисунок из четырёх оставил ребёнку угадывать, какая латинская буква кто: полосы `A │▒▒│▒▒│` и `B │▒▒│▒▒│▒▒│` к задаче «40 конфет поделили между Аней и Борей в отношении 2 к 3». Прямая проверка (от вопроса к рисунку, R59) этого не видит: вопрос латинских меток не называет вовсе.

Для сравнения: из 24 эталонных рисунков все называют свои метки, из 11 двойников каркасов — 3.

**Решение: обратная проверка нужна** и сделана мягкой, как просила задача. Метка названа, если вопрос называет её:

- отдельным словом, к которому не примыкают латинские буквы (с диакритикой тоже) и цифры: в письме без пробелов «点A在3» называет A, и так же называют «rows A-D», «box A's lid», турецкое «A'dan»; метку-слово — в любом регистре;
- среди заглавных подряд, большинство которых — метки (AB);
- в имени клетки (B2);
- внутри диапазона: две объявленные метки своего рода, отдельно или в именах клеток, а между ними тире, многоточие или не больше трёх слов, которые не перечисляют и не считают — ни слова «и», «или», «с» ни на одном из 22 языков карточек, ни запятой, ни знака действия или сравнения, ни конца предложения. «Rows A to D», «von A bis D», «A부터 D까지», «从A到D», «cells A1 to D4» называют то, что между концами; «точки A и D» и «A в 3, D в 9» — нет.

Одиночная заглавная не считается названной только сразу после числа: там это единица («3 L»). Прямая проверка (R59) по-прежнему принимает за слово и артикль «A» в начале предложения, и «I», а обратная — нет: артикль бывает только в английском, а метка в начале предложения на любом языке тоже стоит перед словом («A y B», турецкое «A kutusunda» — ящик A); «I» от строки I отличает только язык. Проверки расходятся нарочно: каждая ошибается в сторону «не отказывать». Отказ считает неназванные метки и не цитирует их. Каркас без вопроса её пропускает. Задача с Аней и Борей по новым правилам была бы отклонена: «task.question does not name 2 of the labels…».

Правило проверено на диапазоне, записанном так, как его пишет каждый из 22 языков карточек, и на метке в начале предложения на каждом латинском письме. Закрытый список слов диапазона («to», «до», «bis», «到»…) знал их в 10 языках и отклонял диапазон так, как его пишут остальные 12: хинди, арабский, бенгали, урду, индонезийский, турецкий, корейский, вьетнамский, персидский, польский, тайский и нидерландский. Дефис, склеивающий метку со словом, отклонял «rows A-D» везде, а английский артикль, прочитанный на любом латинском письме, — метку A в начале предложения на остальных десяти латинских языках. Поэтому правило перечисляет то, что диапазон разрывает, а не то, что его образует, и артикля не читает. Цена мягкости: связь двух концов в одно-два слова («A beats D») сойдёт за диапазон, а диапазон длиннее трёх слов («from A all the way to D») — нет.

Восемь двойников, чьи вопросы метки не называли, переписаны:

| Двойник | Было | Стало |
|---|---|---|
| `grid-3x3`, `grid-4x4` | робот S → F, вопрос меток не называет | задача Нины `grid-56-d2-1` и робот `enum-56-d3-3`: «rows A to C / A to D, columns 1 to 3 / 1 to 4», клетки A1…D4 |
| `row` | деревья A…B | ларьки ярмарки `ord-56-d2-3`: «The toy stall (T)», «numbered 1 to 5» |
| `timetable` | поезда A и B без названия | `clk-56-d3-1`: «Train A», «Train B» |
| `balance` | чаши A и B | та же задача, метки — гири «1» и «3» из «1 kg and 3 kg», буквы убраны |
| `pouring` | ёмкости A, B, C | та же задача, метки — ёмкости «8», «5», «3» литра |
| `clock-face` | стрелки H и M | та же задача, метка — «4» из «4 o'clock», буквы убраны |
| `number-line` | кузнечик A — но «A» в «A grasshopper sits at 0» артикль | та же задача, метка — «0» из «sits at 0», буква убрана |

У `balance` и `pouring` в темах нет ни одной эталонной задачи, называющей метки, поэтому переводить их было некуда. Метка-число, нарисованная как есть, проходит обе проверки. Руководство модели теперь говорит то же: «leave out a label the question has no use for; a number the question gives, drawn as it stands, can be a label too». Каркасы часов, весов и переливаний больше не настаивают на своих буквах: назвать их в вопросе или убрать, и тогда метками станут числа из вопроса.

## Что проверить в T62 и T63

- `just drawings`, рисунки 1–18, в Claude (веб, телефон) и в ChatGPT (веб, телефон): рамка 30 ячеек без прокрутки на телефоне, 32 и шире — с прокруткой внутри рамки; 12 строк — вопрос, рисунок и варианты на одном экране; рисунки 12–15 ровные, рисунок 16 (исключённые символы) съезжает хотя бы на одной поверхности — иначе исключение было бы лишним; на iPhone — не рисуются ли `↔↕▪▫` в его последней строке цветными эмодзи: из-за этого их и исключили.
- Как часто обратная проверка отклоняет задачи и за что. В логах у всех трёх сверок рисунка один код, `drawing_mismatch`, так что какая сработала, видно только в ответе инструмента в самом чате («task.question does not name N of the labels»). Ложный отказ стоит ребёнку попытки; если модель пишет диапазоны так, что правило их не узнаёт, — поправить правило или руководство.
- Кнопки оценок на карточке калибровки: на телефоне в Claude ни одна оценка до сервера не дошла. Нажимали ли их — неизвестно; если нажатие теряется, это то же, что `submit_answer` с карточки урока.

## Замечания

1. **Claude Code присылает части задачи объектами, claude.ai — строками (R137).** Все 13 вызовов `submit_task` в `just play` пришли объектами; в claude.ai в T53.2 — строками. Разница — в клиенте, не в модели.
2. **Пустой `brief.setting`.** В `fractions.parts` первая попытка отклонена `bad_structure: brief.setting is missing or empty`, вторая принята. Модель исправилась сама, но одна попытка ребёнка потрачена; стоит проследить в T62 и T63, как часто это бывает.
3. **Рисунок с равенствами.** Полосы к задаче про конфеты несли строки `A + B = 40` и `B = ?`. Формат это разрешает, руководство — нет («write no words or units in the drawing» говорит о словах и единицах, равенства не упоминает). Оставлено как есть.

## Метод и его пределы

Замер повторяется так (витрина должна быть поднята: `just web-preview`; сценарии замера лежат в рабочей папке сессии):

```bash
docker run --rm --network host -v "$PWD":/data -w /data mcr.microsoft.com/playwright:v1.63.0-noble \
  bash -c 'apt-get update -qq && apt-get install -y -qq fonts-dejavu-core fonts-noto-mono && node measure.mjs'
```

Прогон модели — `just play-server` и `just play -p --output-format stream-json --verbose` по ходу на тему, как в T04.

Чего замер не показывает:

- настоящих шрифтов телефонов: SF Mono и Droid Sans Mono заменены заместителями, чьи метрики и набор символов известны;
- ширины карточки ChatGPT: её покажет T63;
- WebKit на iOS: движок другой, хотя раскладка простого моноширинного блока у движков совпадает.
