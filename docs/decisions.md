## Протокол и SDK

**R01. Go SDK — v1.8.0.** PRODUCT 7 называл v1.7.0; на 2026-09-16 актуальна v1.8.0 (14.09.2026) — патч-релиз без изменений протокола: набор поддерживаемых версий тот же, 2026-07-28 остаётся новейшей. Добавлены лимиты на размер SSE-события, тела запроса и глубину JSON, настройка `ServerOptions.SupportedProtocolVersions` и явный код `-32022` вместо голого 400. Спайк T03 собран и проверен на ней. — *Почему:* строго новее и полностью совместима, держаться прошлого патча незачем. — *Где живёт:* `go.mod` (T17), PRODUCT 7.

**R02. Сервер не сужает список версий протокола.** Работаем только по 2026-07-28 (О-20, О-28), но `SupportedProtocolVersions` оставляем в состоянии по умолчанию: SDK сам предпочитает новейшую версию при согласовании. — *Почему:* в строгом режиме Claude не добавляет коннектор. Перед основной сессией хост шлёт два коротких легаси-`initialize` с пустой версией, и отказ по версии ломает шаг «Connect» (status 400); в обычном режиме те же прогоны целиком идут по 2026-07-28 — ни один настоящий запрос не согласовал версию старее. — *Отвергнуто:* строгий режим «только 2026-07-28» на транспорте; запасной путь stateless 2025-11-25 (О-28). — *Где живёт:* T41; перепроверить в ChatGPT — T63.

## Вход и права

**R03. Регистрация клиентов — CIMD, DCR остаётся запасным.** Метаданные сервера авторизации объявляют `client_id_metadata_document_supported: true`, сервер сам забирает документ по HTTPS-`client_id`; `/register` (RFC 7591) поддерживается ради обратной совместимости. — *Почему:* с 2026-07-28 DCR формально устарел, и Claude вживую пришёл именно с CIMD (`client_id: https://claude.ai/oauth/mcp-oauth-client-metadata`), ни разу не откатившись на DCR; документация ChatGPT тоже рекомендует CIMD, но вживую он не проверен. — *Где живёт:* T07, T47–T49.

**R04. Нехватка прав у инструмента — HTTP 403 с заголовком `WWW-Authenticate`.** Поле `_meta["mcp/www_authenticate"]` в результате вызова добавляется дополнительно, ради ChatGPT, но единственным механизмом быть не может. — *Почему:* живой прогон T04: на 403 Claude сам сходил на `/authorize` за расширенным scope и сам повторил неудавшийся вызов, без участия человека; инструмент, отвечавший только через `_meta`, выглядел для него обычной ошибкой. — *Следствие:* step-up модель не видит — в её контексте один успешный вызов, поэтому её рассказ о состоянии авторизации ненадёжен, судить можно только по логу сервера (это же правило — для всех приёмочных прогонов). — *Где живёт:* T47–T49.

## Инструменты и окружение

**R05. Отдельного файла версий инструментов нет.** Точная версия закрепляется там, где инструмент ставится: `ARG` в `.devcontainer/Dockerfile`, литерал в `devcontainer.json` и `devcontainer-lock.json`, версия модуля в `go.mod`, точная версия плюс lock-файл в npm, SHA коммита в GitHub Actions. — *Почему:* один источник правды на инструмент; отдельный файл версий пришлось бы вручную держать в согласии с этими же местами, а сборка всё равно читает версии оттуда. — *Отвергнуто:* общий файл версий; проверка контрольных сумм сверх той, что уже делает `go install`. — *Где живёт:* CLAUDE.md («Exact versions only»), T01.

## Сборка виджета

**R06. Пакет `@modelcontextprotocol/ext-apps` версии 2.0.0; ориентир — библиотека, а не текст спецификации.** Там, где спецификация MCP Apps 2026-01-26 расходится с библиотекой — в `ui/message` и `ui/update-model-context` поле `content` у неё всегда массив блоков, а не одиночный объект, — пишем по библиотеке. — *Почему:* её код и есть реальный рантайм хостов; расхождение найдено в T03 при сборке виджета. — *Где живёт:* T42, `web/package.json`.

## Инструкции для модели

**R07. Тексты для модели не полагаются на точное имя инструмента.** Claude префиксует имена именем коннектора (`MathTrail:show_widget`). Инструкции описывают инструменты по назначению и по имени без префикса, не требуя дословного совпадения; в текстах для ребёнка и родителя имён инструментов нет вовсе. — *Почему:* префикс добавляет хост, и у каждого хоста он свой; инструкция, завязанная на точное имя, ломается при смене хоста. Найдено в живом прогоне T03. — *Где живёт:* T36; перепроверить в ChatGPT — T63.

## Контент для модели

**R08. Шаблоны решателей лежат в `content/solvers/`, по одному-два на тему.** Шаблон — короткая программа по контракту решателя с помеченными местами под числа условия, обобщённая из уже написанного решателя эталона; в комментарии — id этого эталона. Сборщик пакета кладёт шаблоны только выбранной темы и остаётся в бюджете размера; в инструкциях шаблон назван образцом, от которого можно отступить. — *Почему:* решатель — единственная программная гарантия того, что верный вариант один (PRODUCT 4.3), и ошибка в нём стоит ребёнку целой попытки; разобранный типовой перебор снимает самую частую причину `solver_error` у слабой модели. — *Отвергнуто:* обязательный каркас — задачи подгонялись бы под то, что умеет шаблон; отсутствие шаблонов вовсе (О-43). Риск однообразия гасят чередование тем правилом (T27) и проверка дублей (T32). — *Где живёт:* T36a, T36.

**R09. Каркасы текстовых рисунков лежат в `content/drawings/`.** Каркас общий, без чисел конкретной задачи, со структурным описанием объектов и связей; модель вписывает числа и метки. Каждый каркас сам проходит проверку формата с пределами по умолчанию — иначе он не каркас. — *Почему:* рисунок перестаёт зависеть от того, что модель помнит о псевдографике, и проверка формата (О-11а) чаще проходит с первой попытки. — *Отвергнуто:* только правила рисования в инструкциях, без заготовок (О-44); свободный рисунок при этом остаётся допустимым и проверяется теми же пределами. — *Где живёт:* T36b, T36; после калибровки пределов каркасы перепроверяются в T58.

## Проверки задачи

**R10. Разбор неверного варианта проверяется детерминированно, без оценки смысла.** Четыре условия: тексты четырёх дистракторов попарно различны; текст не совпадает с решением и подсказкой и не является их началом; текст не равен дословному описанию ловушки из каталога; текст не короче минимума по письменности (слова, а для CJK и тайского символы). Отказ идёт своим кодом и называет вариант, который надо починить. — *Почему:* «ошибка — это диагноз» — одна из трёх опор продукта (PRODUCT 1), а в текстовом режиме разбор и есть главная польза. — *Отвергнуто:* только инструкции и эталоны без программной проверки; любые эвристики «осмысленности» — при медиане генерации 69 секунд лишняя строгость стоит ребёнку ещё одной попытки (О-46). — *Где живёт:* T32a, код отказа — T12.

## Виджеты и показ прогресса

**R11. Блока «Совет взрослому» в v1 нет.** Карточка задачи остаётся детской: ни скрытого блока с наводящими вопросами, ни отдельного инструмента только для виджета, ни вопросов в запечатанном блоке. — *Почему:* решение автора (О-45) — взрослый ведёт ребёнка сам, а наводящие вопросы получает у модели в самом чате. — *Следствие:* задача T55a удалена, формулировка раздела 1 PRODUCT переписана; если предложение вернётся, оно снова проходит через вопрос в 12.2. — *Где живёт:* PRODUCT 1, 2, 4.2.

**R12. Звание поверх числа рейтинга.** Пять ступеней, границы считаются из коридора рейтинга, названия — ключи словарей локалей. В профиле звание не хранится: это функция показа, а не данные. — *Почему:* «1500» семилетке ничего не говорит, а сама шкала при этом не меняется (PRODUCT 4.5). — *Где живёт:* T57, ключи — T54, переводы — T59 (О-48).

**R13. Ритм занятий не показывается.** Ни счётчика решённых за день в профиле, ни счёта по хвосту истории, ни серий, штрафов за пропуск и напоминаний. — *Почему:* решение автора (О-49) — прогресс остаётся про знание, а не про количество; давить на регулярность у пользователя 7–10 лет неуместно (PRODUCT 10). — *Где живёт:* T09 и T57 остаются без изменений.

## Границы v1

**R14. Печатных листов задач в v1 нет.** Инструмента, который отдаёт взрослому 3–5 проверенных задач одним текстом, не будет. — *Почему:* профиль хранит отпечатки прошлых задач, а не тексты (О-40), поэтому лист собирается только из задач, сгенерированных тут же: 3–5 генераций подряд — это лимит сообщений бесплатного тарифа, свой расчёт дневного лимита и, по сути, возврат к отменённому буферу задач (О-6). — *Где живёт:* PRODUCT 2 («не входит»); отдельная задача в фазе 7 не заводится (О-47).
