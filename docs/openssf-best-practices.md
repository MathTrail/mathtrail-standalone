# OpenSSF Best Practices — the answers, ready to be transcribed

Draft answers for the **passing** level of the [OpenSSF Best Practices](https://www.bestpractices.dev) questionnaire, one row per criterion, with the evidence a reviewer would look for. Transcribe into the web form; the project URL is `https://github.com/MathTrail/mathtrail-standalone`.

Keep this file current when a criterion's answer changes — the badge is re-confirmed rather than earned once.

## Before the form is submitted

| What | Why |
|---|---|
| Write `CONTRIBUTING.md` | Two criteria (`contribution`, `contribution_requirements`) ask for a documented contribution process, and the repository has none. It is also the place to say what О-4 already decided: the code is MIT, the name is not. |
| Enable private vulnerability reporting | `vulnerability_report_private` rests on it, and [`SECURITY.md`](../SECURITY.md) already points there. |

Everything else below is already true.

## Security

| Criterion | Answer | Evidence |
|---|---|---|
| `know_secure_design` | Met | [`docs/architecture/02-auth.md`](architecture/02-auth.md) — the trust boundaries, what is sealed, what the service refuses to hold |
| `know_common_errors` | Met | the same, plus R16: the one field a person writes and a model reads travels as data, never as instructions |
| `crypto_published`, `crypto_call`, `crypto_floss` | Met | XChaCha20-Poly1305 and HKDF-SHA256 from `golang.org/x/crypto`; nothing invented here |
| `crypto_keylength` | Met | 256-bit keys, 192-bit nonces |
| `crypto_working`, `crypto_weaknesses` | Met | SHA-256 only; no MD5 or SHA-1 anywhere a security decision depends on it |
| `crypto_pfs` | Met | TLS terminated by Google's frontend with forward secrecy |
| `crypto_password_storage` | N/A | there are no passwords: sign-in is Google's, and no credential of a user is ever stored |
| `crypto_random` | Met | `crypto/rand` |
| `delivery_mitm`, `delivery_unsigned` | Met | HTTPS everywhere; release artifacts signed with keyless cosign (R40); every base image pinned by digest, every action by commit |
| `vulnerabilities_fixed_60_days`, `vulnerabilities_critical_fixed` | Met | `govulncheck` and a Trivy scan of the runtime image fail the checks; Dependabot proposes the bumps weekly |
| `no_leaked_credentials` | Met | `gitleaks` over the entire history on every pull request; secrets live in Secret Manager and reach the service through its environment |
