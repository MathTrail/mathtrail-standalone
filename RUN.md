# RUN.md — план реализации MathTrail v1

> Что строим — [PRODUCT-V1.md](PRODUCT-V1.md); как строим — `SPEC.md`, его пишут задачи T11–T15. Этот файл задаёт порядок работы: маленькие задачи, которые запускаются по одной. После каждой задачи я проверяю результат и только потом запускаю следующую. Материалы прототипа — в [docs/prototype/](docs/prototype/README.md) и в локальной копии `prototype/`.

## Как пользоваться

Задача запускается одной фразой в новой сессии Claude Code внутри devcontainer:

```
Выполни задачу T07 из RUN.md
```

**Правила для исполнителя (Claude):**

1. Делать только указанную задачу. Файлы других задач не трогать, кроме того, что задача прямо требует.
2. Сначала прочитать [CLAUDE.md](CLAUDE.md), саму задачу и разделы PRODUCT-V1 и SPEC, на которые она ссылается. Затем — `docs/decisions.md` (с T05) и материалы прототипа, если задача на них ссылается. Если задача противоречит PRODUCT-V1 или SPEC или чего-то не хватает — остановиться и спросить, а не додумывать. Дыры записываются открытыми вопросами (PRODUCT-V1 12.2) или в раздел «Замечания» документа, над которым идёт работа.
3. Начиная с T02, работать только внутри devcontainer (T00 и T01, которая создаёт контейнер, выполняются на хосте). Если сессия запущена не в нём, остановиться и попросить открыть проект в контейнере.
4. Своих вызовов LLM API в продукте нет. Живые прогоны в Claude и ChatGPT расходуют лимиты моих подписок, а действия в Google Cloud могут стоить денег. До начала — предупредить и назвать ожидаемую стоимость.
5. Код SDK, протоколов и API не писать по памяти: сначала свериться с документацией закреплённой версии (go-sdk, MCP Apps, Drive API, starlark-go, Google OAuth).
6. Задача с кодом заканчивается зелёными `just ci-lint` и `just ci-test` (с T17), а если задача трогает `web/` — ещё и проверками виджета (с T42).
7. Не коммитить. Коммит делаю я после проверки.
8. В конце — короткий отчёт по-русски: что сделано, какие файлы, как проверить (команды), что осталось открытым.
9. После выполнения отметить задачу в сводной таблице: `[ ]` → `[x]`.
10. Язык:
    - код, **все комментарии в коде и конфигах**, инструкции и контент для модели, `CLAUDE.md` и `README.md` — строго на английском;
    - документы и отчёты — на русском.
11. Если задача оказалась больше, чем на одну проверку (≈ 30–60 минут чтения), — до начала предложить, как её разбить.

**Статусы:** `[ ]` — не начата, `[x]` — выполнена (отмечает исполнитель). Если при проверке что-то не так, возвращаю задачу в `[ ]` и пишу, что поправить.

## Фаза 5. Вход, Drive, лимиты

### T47. OAuth: метаданные и клиенты

- **Цель:** хост находит наш сервер авторизации и регистрируется.
- **Сделать:** `internal/oauth`:
  - метаданные ресурса (обработчик go-sdk) и сервера авторизации (S256, `iss` и прочее по T07);
  - **CIMD:**
    - только HTTPS;
    - DNS-проверка без приватных, loopback и link-local адресов и metadata-сервера;
    - соединение с проверенным IP;
    - без редиректов;
    - лимиты размера и времени;
    - кеш в памяти;
    - `client_id` совпадает с URL;
  - DCR без состояния (запись запечатана в `client_id`);
  - точная сверка redirect URI;

  - `securitySchemes` и `_meta["mcp/www_authenticate"]` по SPEC.
- **Тесты:** фейковый сервер CIMD; каждая SSRF-ловушка; поддельный DCR `client_id`; неверный redirect URI.
- **Разделы:** SPEC: OAuth; PRODUCT 6, 9.3.

### T48. OAuth: authorize, согласие, callback

- **Цель:** родитель входит через Google и разрешает доступ клиенту.
- **Сделать:**

  - CSRF-cookie;
  - редирект в Google (`openid`, `drive.file`, офлайн-доступ, PKCE к Google);
  - callback:
    - проверка `state` и cookie;
    - обмен кода Google;
    - проверка ID-токена;
    - наш запечатанный код (короткий срок, привязан к клиенту, redirect URI, challenge, resource);
    - редирект с `code`, `state`, `iss`;
  - ошибки по RFC.
- **Тесты:** фейковый Google; подмена `state`; нет cookie; истёкший код Google; отказ пользователя.
- **Разделы:** SPEC: OAuth; PRODUCT 6 (О-7, О-22).

### T49. OAuth: token, refresh, revoke, bearer

- **Цель:** хост получает токены, сервер проверяет их на каждом запросе.
